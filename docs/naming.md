# 命名与包名

## 中文名：屙了么

保持。三个字，谐音"吃了吗"，问候语结构天然带社交传播性——这个不用再讨论。

## 英文名：PoopedYet

**结论：留着，挺好。** 它是目前几个候选里唯一同时做到"对应中文名"和"不那么粗俗"的。

**好在哪**

- 结构上精确对应中文名：「Pooped yet?」就是「屙了么？」
- **有第二层意思**：`pooped` 在英语口语里的主要义项其实是「累瘫了」，所以「Pooped yet?」也读得通"累了吗？"。对一个记录如厕的 App 来说这层双关是加分项——它让名字在上架应用商店、给别人看手机时都不至于尴尬。
- 好记、好搜。查过了，**没有重名 app**（相近的有 Poopy、Pooding、didyoupoop.today，都不冲突）。

**要注意的**

- 它是个疑问句片段，不是名词，所以没法当动词或名词用。UI 文案里当品牌名没问题（"打开 PoopedYet"），但造不出"PoopedYet 一下"这种说法。
- 中文用户口口相传时说的是中文名，英文名实际只出现在包名、仓库名、商店标题上——所以"发音难度"这件事的影响比想象中小。
- `poop` 类 App 在商店里挺多的，但 `PoopedYet` 靠 `yet` 这个词反而有辨识度。

**备选（如果哪天想换）**

| 名字 | 含义 | 优势 | 风险 |
|---|---|---|---|
| **NumberTwo** | 英语里最经典的委婉说法 | 最体面，健康向，商店搜索友好 | 太常用，大概率已被占；少了点性格 |
| **PoopDex** | 图鉴，暗示长期记录与统计 | 最有个性，贴合日历 + 统计的产品形态 | `-dex` 这个后缀已经有点烂俗 |
| **Regular** | 双关：既指"规律的"，也是体检话题 | 最聪明的一语双关 | 太难搜；容易被误认成别的 App |
| **SitLog** | 含蓄，"坐着的时候" | 低调体面，什么场合都能念出口 | 平淡，没有记忆点 |
| **WCLog** | WC 在国内认知度极高 | 国内传播成本最低 | 国外不通用；"WC"稍显土 |

**商店标题建议**：`屙了么 PoopedYet` —— 中文用户搜"屙了么"、英文用户搜 poop tracker 都能命中，两个名字互相导流。

## 包名（applicationId）

### Android 的硬约束

- 至少两段，点号分隔
- **每段必须以字母开头**
- 只能用字母、数字、下划线
- 不能是 Java 关键字
- **上架后永远不能改**——改了就是另一个 App，老用户收不到更新
- Play Store 全局唯一
- 不能用 `com.example`（直接拒审）

### 推荐：`com.poopedyet.app`

反写域名的标准形式，尾段 `app` 表明这是主应用模块。

### 其他选项

| 包名 | 适用场景 |
|---|---|
| `com.poopedyet.app` | ← **推荐**。不打算注册域名时最稳妥 |
| `app.poopedyet` | 更短更干净。前提是你拥有 `poopedyet.app` 这个域名（反写域名是标准做法） |
| `io.github.<你的用户名>.poopedyet` | 打算开源到 GitHub 时。天然对应 `github.io` 域名，且几乎不可能和别人撞车 |

### 要避开的

- `com.example.poopedyet` —— Play Store 直接拒
- `com.poopedyet` —— 两段是合法的，但太"裸"，且容易和别人占的 `com.poopedyet.*` 混在一起
- 下划线 —— 合法但不规范
- 中文、连字符、数字开头 —— 非法

### 两个必须现在定下来的点

1. **包名和签名证书是绑死的。** 以后想换包名 = 重新发一个 App，老用户全部丢失。现在定了就别改。
2. Gradle 里的 `namespace` 和 `applicationId` 技术上可以不同，但**建议保持一致**，省得以后自己都分不清哪个是哪个。

### 顺带

Dart 侧的 pubspec 包名必须是合法标识符（全小写 + 下划线），所以是 `pooped_yet`，不是 `PoopedYet`。
