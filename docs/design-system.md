# 屙了么 · UI 设计规范 v0.1

> 配套视觉稿：`.design/ui-reference.html`（可编辑源文件）+ `.design/ui-reference.png`（渲染图）

---

## 1. 设计方向：便签手帐 / Paper Journal

**为什么是这个方向**

这个 App 的题材有两面性：一面是**很日常的健康记录**（值得认真对待、要好查），另一面是**有点羞耻又有点好笑的梗**（"屙了么"本身就是"吃了吗"的谐音）。纯医疗风会显得冷冰冰、大材小用；纯恶搞风又会让人不想认真记。

所以选**纸质手帐**：暖米色纸面 + 贴纸感的头像徽标 + 略带手写性格的标题字。它同时满足了三件事——

1. **消解尴尬**：纸感比纯白医疗界面更私密、更像"自己的小本子"。
2. **天然适配日历**：手帐本来就是"日历 + 贴纸"的信息组织方式，头像徽标就是贴纸。
3. **和日程类 App 拉开距离**：不学 Google Calendar 的蓝白商务感，也不学 iOS 日历的极简灰。

**一句话气质**：像一本放在洗手间台面上的、贴满了小贴纸的纸质台历。

## 2. 色板

所有文字色都经过 WCAG 2.1 AA 实算，不是眼挑的。括号里是对 `--paper` 的实测对比度。

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#FAF5EC` | 页面底色，暖米纸 |
| `--paper-deep` | `#F2E9DA` | 次级底、分段控件槽、chip 底 |
| `--surface` | `#FFFFFF` | 卡片 |
| `--surface-2` | `#FFFCF6` | 周视图格底 |
| `--ink` | `#2E2622` | 主文字（深咖，**不用纯黑**）— 13.4:1 |
| `--ink-2` | `#6B5B4E` | 次级文字 — 5.98:1 |
| `--ink-3` | `#756552` | 三级文字、占位 — 5.17:1 |
| `--ink-4` | `#9C8C74` | **仅限非文本**：拖拽把手、装饰图标 — 3.27:1 |
| `--line` | `#E9DDCA` | 描边、虚线分隔（纯装饰） |
| `--brand` | `#C8783C` | **仅限 ≥24px 大字或纯装饰填充** — 3.11:1 |
| `--brand-ink` | `#9A5219` | 焦糖色**文字**（周末日期、链接、加号） — 5.38:1 |
| `--brand-fill` | `#A85F29` | 焦糖色**底**，上面放白字 — 白字 4.85:1 |
| `--brand-soft` | `#F7E5D2` | 主色浅底（计数药丸、图标底） |
| `--off` | `#B03A2E` | 休（法定假日）实心角标，白字 6.01:1 |
| `--work` | `#4A7C8C` | 班（调休上班）实心角标，白字 4.61:1 |
| `--live` | `#3F7A57` | 正在屙（脉冲点、卡边） — 5.08:1 |

**用色纪律**

- 主色是**焦糖**不是棕色。真实的"屎棕色"在屏幕上会脏、会腻，焦糖保留了暖调联想但干净得多。这是整个方案里最关键的一次取舍。
- 阴影一律用暖调 `rgba(94,66,42,·)`，**绝不用中性灰**。灰阴影配米色底会立刻显出"廉价 Material 默认感"。
- 描边用 1px 米色代替重阴影做分隔，这是手帐感的重要来源。
- 休/班是**功能色**，只出现在日期格右上角，面积越小越有效。

### ★ 焦糖一色三分

早期版本只有一个 `--brand` 到处用，结果三种场景的对比度要求完全不同，全都不达标。现在按**用途**分家：

| 令牌 | 什么时候用 | 为什么 |
|---|---|---|
| `--brand` | ≥24px 的大字、纯装饰填充 | 大字只需 3:1，浅一点的焦糖更好看 |
| `--brand-ink` | 任何焦糖色**文字** | 文字需要 4.5:1，必须压深 |
| `--brand-fill` | 焦糖色**底**，上面盖白字 | 白字需要 4.5:1，底必须压深 |

**踩过的坑**：白字放在 `--brand` 上只有 3.38:1，看起来"挺清楚"，实测不达标。
主按钮、FAB、选中日期格、默认标签、分段控件——全部中招。

### ★ 对比度自检

色值靠眼睛判断是不可靠的：这套色板初版有 **355 处文本 + 50 处图标**不合格，
而肉眼看完全正常。

```powershell
# 用法见 .design/README-layout-check.md
```

规则：

- 普通文本（< 24px）≥ **4.5:1**；大字（≥24px，或 ≥18.66px 且粗体）≥ **3.0:1**
- 图标等非文本 ≥ **3.0:1**
- 有意降级的元素（非本月日期）加 `a11y-dim-ok`，自检会归到「已声明降级」

**改任何颜色之后必须重跑。**

## 3. 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 标题 / 月份 / 日期数字 / 按钮 | **得意黑 Smiley Sans** | 斜体、有性格、免费商用（SIL OFL） |
| 正文 / 备注 / 说明 | **Noto Sans SC** | 400 / 600 / 700 / 800 |

**为什么选得意黑**

中文 App 最容易翻车的地方就是字体——绝大多数项目直接用系统默认黑体，结果和所有 App 长一个样。得意黑是为数不多的、**免费可商用**且**有强烈性格**的中文字体：笔画有粗细对比、整体带斜切，很适合"玩梗但不廉价"的调性。用在标题、月份、日期数字上，整个界面的辨识度立刻起来。

注意它是 oblique（斜体），**不适合长段落正文**——所以正文交给 Noto Sans SC，形成"有性格的标题 + 克制的正文"的对比。

> 字体文件需打包进 `assets/fonts/`，并在 `pubspec.yaml` 声明。中文子集化后包体约 1.5–3MB，可接受。本地已下载到 `.design/fonts/smiley/`。

**字号阶梯**

| 层级 | 字号 | 字重 |
|---|---|---|
| 页面标题 | 25 | 得意黑 |
| 区块标题 / 日期栏 | 17.5 | 得意黑 |
| 记录人名 / 时间 | 14 / 12.5 | 800 / 600 |
| 正文备注 | 12.5 | 400 |
| 辅助说明 | 11 | 400 |
| 格内角标 | 8.5 | 800 |

**所有数字启用 `tabular-nums`**。日历是严格网格，数字宽度不一致会让整列抖动——这是日历 UI 最常见的低级瑕疵。

## 4. 形状与质感

| 项 | 值 |
|---|---|
| 圆角 | 卡片 20 · 日历格 13 · 周格 14 · 弹层顶部 28 · 药丸 99 |
| 间距基数 | 4 / 8 / 12 / 16 / 20 / 24 |
| 阴影 1 | `0 1px 2px rgba(94,66,42,.05), 0 4px 12px rgba(94,66,42,.05)` |
| 阴影 2 | `0 2px 6px rgba(94,66,42,.07), 0 12px 28px rgba(94,66,42,.09)` |
| 背景质感 | 焦糖 + 抹茶双径向光晕 + SVG `feTurbulence` 纸面噪点（opacity .22, multiply） |

噪点层是"纸感"的来源。没有它，暖米色只是"偏黄的白色"；有了它，屏幕才开始像纸。实现上用一张 200×200 的平铺 SVG 噪点即可，成本极低。

## 5. 日历单元格规格 ★

这是整个 App 信息密度最高、也最容易做坏的组件。

```
┌──────────────────┐
│ 11          休   │   ← 日期数字 / 休·班角标（仅法定调休日出现）
│ ┌──┐             │
│ │🐶│ 2           │   ← 头像 14px 圆形 + 次数
│ └──┘             │
│ ┌──┐             │
│ │🐱│ 1  +1       │   ← 第 2 行；剩余人折叠为 +N，与末行同行
│ └──┘             │
└──────────────────┘
```

| 属性 | 月视图 | 周视图 |
|---|---|---|
| 列数 × 列宽 | 7 × 46px | 7 × 46px |
| 格高 | 58px | 132px |
| 内边距 | 3 / 3 / 2 | 6 / 3 / 7 |
| 圆角 | 13px | 14px |
| 头像尺寸 | 14px 圆形 | 14px 圆形 |
| 最多显示行数 | 2 | 3 |
| 溢出 | `+N` 与末行同行 | `+N` 与末行同行 |
| 行间距 / 徽标内距 | 2 / 2 | 3 / 2 |

**状态**

| 状态 | 表现 |
|---|---|
| 今天 | 焦糖 1.5px 内描边（`inset box-shadow`）+ 数字焦糖 + 底 `#FFFBF5` |
| 选中 | 焦糖实心填充 + 暖调投影；数字转白，头像换白底，计数转白 |
| 今天 ∩ 选中 | 选中态优先 |
| 非本月 | 数字 50% 透明，徽标 40% 透明 |
| 周末 | 日期数字用焦糖色（`--brand`）区分 |
| 休 / 班 | 右上角 8.5px 角标，底色 `--off-soft` / `--work-soft` |

**关键实现约束**

- **溢出必须与末行同行**。如果 `+N` 单独占一行，2 行徽标就会变成 3 行，在有 3 个屙屎人的日子直接撑破 58px 格高——这是我在第一版渲染中实测到的真实缺陷（溢出 11px 被裁切）。正确做法是把徽标按"行"组织，`+N` 追加到最后一行内。
- 格内所有元素 `flex:none` + `white-space:nowrap`，禁止挤压缩放导致头像变形。
- 数字用 `tabular-nums`，7 列严格对齐。

## 6. 组件速查

**记录卡**
- 38×38 圆角 13px 头像块（底色由屙屎人配色决定）+ 姓名 14/800 + 时长 10.5/700
- 时间行 `09:12 → 09:26`，`→` 用弱化色
- 进行中：时间行替换为脉冲点 + 绿字"进行中"，卡片描边转为 `--live` 40% 透明
- 备注区：上方 1px 虚线分隔，每条 = 焦糖时刻 + 正文，行距 1.45

**快捷备注 chip**
`11.5/700`，药丸，白底 + 米色描边；"＋ 自定义"用焦糖虚线描边 + 透明底。点击即插入并记下当时时刻。

**底部弹层**
顶部 28px 圆角 + 36×4 grabber；字段标签 `11/800` + 字距 .1em（全大写感的中文用法）；时间选择用两张并排小卡，未结束的那张显示"未结束 / 点此补填"而不是留空。

**FAB**
焦糖渐变药丸，`＋ 现在开屙`。这是首页唯一的高饱和元素，视觉权重必须压过一切。

**空状态**
不要写"暂无数据"。建议写"这天还没有人屙过"这类带角色感的文案。

## 7. 图标规范

**全部用 Lucide，禁止 emoji。**

emoji 在不同 Android 版本 / 厂商 ROM 上渲染差异极大（三星、小米、原生各画一套），同一份设计稿在真机上会散架；而且彩色 emoji 会在焦糖+米色的低饱和体系里跳出来，把整体质感拉low。矢量图标走 `currentColor`，颜色完全由设计系统控制。

| 项 | 值 |
|---|---|
| 图标库 | **Lucide** v1.55.0（ISC 协议，可商用） |
| 规模 | 2141 个图标，本稿用到 73 个 |
| 网格 | 24×24，描边 2px，圆角端点 |
| Flutter 包 | `lucide_icons_flutter` 3.1.25 |
| 着色 | 一律 `stroke="currentColor"`，颜色继承父级 |

**尺寸阶梯**

| 场景 | 尺寸 |
|---|---|
| 日历格内头像图标 | 9px |
| 内联小图标（箭头、计数前缀） | 12–14px |
| 列表行 / 按钮 / 输入框 | 15–17px |
| 头像内图标 | 13 / 18 / 20 / 38px（随头像尺寸） |
| 空状态 | 32px |

**实现方式**：图标以 SVG 雪碧图内联在页面里，用 `<use href="#i-名字">` 引用，尺寸由 CSS 变量 `--s` 驱动。生成脚本 `.design/build-icons.mjs`（幂等，可重复运行）。Flutter 侧直接用 `lucide_icons_flutter` 的 `LucideIcons.xxx`，不打包 SVG。

**备选**：Phosphor（6 种字重，`phosphor_flutter` 2.1.0，MIT）、Material Symbols（7000+，`material_symbols_icons`）。选 Lucide 是因为它的 2px 圆头描边和手帐调性最搭；Material 的默认填充风格太"安卓系统"。

## 8. 头像策略

用户上传的头像大概率是随手拍的照片，直接塞进 14px 圆形会糊成一团。

**三级兜底（已确认采用）**

1. **内置图标头像** — 从 Lucide 里选一组（dog / cat / rabbit / bird / turtle / fish / ghost / star / crown / rocket / leaf / zap），配固定色板上的底色和前景色。零配置、零联网、在日历格里也能一眼区分。
2. **首字色块** — 没选图标时用姓名首字 + 按 `name.hashCode()` 取色，保证同一个人颜色永远一致。
3. **上传照片** — 居中裁剪为正方形，**缓存一份 96px 缩略图**供日历使用（不要每次从原图缩，日历一屏要画几十个头像）。

> 早期版本用 emoji（🐶🐱🐻）做头像占位，已废弃 —— 见第 7 节。

## 9a. 首次打开：静默建档，不弹墙

**问题**：全新安装时数据库是空的，而 FAB「现在开屙」依赖默认屙屎人。
「空状态」这件事被漏掉了 —— ⑨ 画的是"某天没记录"（日历是满的），不是"什么都没有"。

**定下来的方案**：

1. **首次启动静默创建一条 `Pooper{ name:'我', isDefault:true }`**，用户无感。
2. 主页日历下方出现**一条可关闭的提示条**（⑳）：
   ```
   [users]  已自动创建「我」              [去添加] ✕
            家里还有别人要记？可以加多个屙屎人
   ```
3. 关掉或点过「去添加」之后**永不再出现**（存一个 `firstRunHintDismissed`）。

**为什么不做引导页**：这个 App 的核心动作是"一次点击开屙"。
在它前面竖一道"先填名字选头像"的墙，是用最贵的位置解决最便宜的问题。
「屙屎人」这个特色用一条提示条就能交代，不值得挡路。

**注意**：这个逻辑不能只写在"首启"分支里 ——
**归档掉最后一个人也会回到"一个都没有"的状态**（见下面 §9d）。

## 9b. 日历的快速切换

早期只做了「‹ › 翻一月 + 月/周分段控件」。从 2026年2月 回到 2024年8月要点 18 次，
这在实际使用里是走不通的。补了四件事：

| 交互 | 位置 | 解决什么 |
|---|---|---|
| **标题可点**（带 ▾） | 月视图/周视图的标题 | 点开年月 / 周选择器，任意跳转 |
| **年月选择器** | ⑰ | 年条横滑 + 12 月网格。**有记录的月带焦糖点**，一眼看出哪几个月有数据 |
| **周选择器** | ⑱ | 该月每一周的日期区间 + 次数。跨月那一周（如 2/23–3/1）点进去会自动切月 |
| **回到今天** | 日期栏右侧 | 翻远了之后一键回来 |

两个必须分清的状态 —— 选择器同时显示「你在看哪个月」和「今天是哪个月」：

- **焦糖实底** = 正在查看的月
- **焦糖细环** = 今天所在的月
- **焦糖小点** = 该月有记录；灰点 = 没有

「回到今天」放在**日期栏**而不是日历头部，原因是头部横向只剩约 2px 余量放不下
（标题 + ▾ + 两个箭头 + 月/周分段控件已经占满 332px 中的 330px）；
而且日期栏本来就在回答"现在看的是哪一天"，语义上也更合适。
只有在**不在今天**时才出现。

### ★ 日历行数必须按月份实算

这是一个真 bug，写下来免得再犯：

```js
const offset = (first.getDay() + 6) % 7;              // 周一作首列
const days   = new Date(y, m + 1, 0).getDate();
const rows   = Math.ceil((offset + days) / 7);        // 5 或 6，不能写死
```

早期版本写死 `for (i = 0; i < 35; i++)`。**2026 年有 3 个月需要 6 行**：

| 月份 | 1 号 | 偏移 | 天数 | 行数 | 旧代码后果 |
|---|---|---|---|---|---|
| 3 月 | 周日 | 6 | 31 | **6** | 丢掉 3/25–3/31 |
| 8 月 | 周六 | 5 | 31 | **6** | 丢掉 8/25–8/31 |
| 11 月 | 周日 | 6 | 30 | **6** | 丢掉 11/24–11/30 |

**为什么一直没发现**：视觉稿的样例月份是 2026 年 2 月（周日开头 + 28 天 = 34 格），
正好落在 5 行以内。用"刚好合适"的数据验证，等于没验证。
⑲ 专门画了 8 月来盯这个。

6 行比 5 行高 61px，卡片是自适应的；记录列表本来就在下面滚动，不受影响。

## 9c. 备注输入：文本域 + 快捷备注

备份一份需求原文：「可以给每次拉屎添加备注，可以是多条备注，备注也有实时的时间和备注信息」。

**主输入是一个多行文本域**（`min-height: 76px`，右上角 `0/200` 字数），
**快捷备注 chip 点一下把文字追加进文本域**，不是各自生成一条。
点「添加这条备注」时，整个文本域内容存为**一条带时刻的备注**。

```
备注                                   2 条
[拉肚子] [很顺畅] [有点干] [带薪摸鱼] [+自定义]
┌────────────────────────────────────┐
│ 昨晚火锅太辣了，有点拉肚子            │
│                                    │
└────────────────────────────────────┘
                          12/200  [添加这条备注]
─────────────────────────────────────
09:14  开冲，很顺畅
09:20  昨晚火锅太辣了，有点拉肚子
```

为什么这样拆：

- **文本域承担"能写长"**。单行输入框写不下「昨晚火锅太辣了，有点拉肚子，今天肚子一直咕噜响」。
- **chip 承担"快速"**。常见情况（拉肚子 / 很顺畅）不该让人打字。
- **两者是叠加关系，不是二选一**：chip 只是帮你把字填进去，填完还能改。
- **列表仍然一条一条带时刻**，满足"多条备注 + 实时时间"这条硬需求：
  09:12 记一条、09:20 再记一条，是这个 App 的核心体验。

> 另一种可能的设计是「一个记录 = 一个备注字段」，但那会丢掉"实时时间"这条需求，所以没采用。

## 9d. 屙屎人的生命周期（三个已定的决策）

### 1. 删人 = 归档，不是真删 ★

数据模型只定义了备注的级联删除，**从没定义删人时他的记录怎么办**。
按最自然的写法（外键 `ON DELETE CASCADE`），删掉"阿狗"会**静默抹掉他几百条历史记录**。

这是不可接受的数据丢失，没有取舍空间：

- `Pooper.archivedAt` 有值 = 已归档，历史记录**原样保留**
- 不再出现在「谁在屙」选择器和默认人候选里
- 日历徽标与统计**仍然计入**（否则日历数字会莫名变小，用户会以为数据丢了），
  但用低饱和显示；设置里给「隐藏已归档」开关
- 归档可撤销
- 真要彻底删除，放进设置页「危险操作」，明确写"将删除 N 条记录"

### 2. `isDefault` 唯一性

```sql
CREATE UNIQUE INDEX ux_default ON poopers(is_default) WHERE is_default = 1;
```

光有索引还不够，两条边界规则必须一起做，否则会在真实使用里炸：

1. **归档 / 删除默认人时**，自动把剩下**最早创建**的那个人提升为默认
2. **如果一个人都不剩**，`isDefault` 全为 null

### 3. 第 2 条会把你打回「一个屙屎人都没有」

这不是首启专属状态 —— **归档掉最后一个人也会回到这里**。

所以「自动建「我」」这套逻辑必须抽成一个可复用的守卫
（`ensureDefaultPooper()`），在**首启**和**归档后**两个时机都调用，
不能只写成 `if (isFirstRun)`。

## 9e. 系统字体放大时日历怎么办

日历格固定 58px，里面塞了日期（14.5px）+ 休/班角标（10px）+ 头像（14px）+ 计数（10px）。

**实测代价**（按各档位算格子需要多高）：

| 系统字体档位 | 单格需要 | 6 行月份共需 | 剩给记录列表 |
|---|---|---|---|
| 1.0×（默认） | 58px | 363px | 充足 |
| 1.3×（大） | ~67px | 417px | 约 136px |
| 1.5× | ~70px | 435px | 约 118px |
| **2.0×（最大）** | **~77px** | **477px** | **约 76px — 列表基本没了** |

安卓可用高度约 553px（844 减去状态栏 / 应用栏 / 日历头 / 星期头 / 日期栏 / FAB 区）。

**定下来的方案**：

1. 日历格内的字号**上限 1.3×** —— 安卓字体档位是 `1.0 / 1.15 / 1.3 / 1.5 / 2.0`，
   1.3 正好是「大」这一档，**常用需求全覆盖**，只有「特大 / 最大」会被截住。
2. 设置页（⑭）给一个**「日历字号」独立三档**（小 / 中 / 大）兜底，
   让需要大字的用户不必受系统档位摆布。
3. 日历卡**外围**的文字（月份标题、星期头、日期栏）**正常跟随系统**，
   只有格子内部被钳制。

**为什么不做自适应格高**：不是懒，是算下来 2.0× 时日历要吃掉 477px，
记录列表彻底消失 —— 那等于用一个功能换掉另一个功能。
**为什么不做完全钳制**：那等于忽略了长辈用户把字体调大的设置，是另一种失职。

**实现**：Flutter 里用 `MediaQuery(data: mq.copyWith(textScaler: TextScaler.linear(min(s, 1.3))))`
只包住 `GridView`，不要包整个页面。

## 10. 记录状态的四副面孔

「没有结束时间」其实是两种状态，视觉上要能一眼分开。判定逻辑见 [tech-stack.md](tech-stack.md#记录状态机修掉永远进行中的-bug)。

| 状态 | 时间行 | 时长列 | 视觉 |
|---|---|---|---|
| **正在屙** | `21:05 → ● 正在屙` | `已 6 分钟` | 苔绿脉冲点 `--live`，卡片左缘一道绿色竖线 |
| **待确认** | `09:12 → ？` | `已超过 2 小时` | 琥珀 `#A9791A`，不做脉冲（避免"还在动"的错觉） |
| **未记结束** | `09:30 → 未记结束` | `时长不详` | 灰 `--ink-3`，无强调 |
| **已完成** | `09:12 → 09:26` | `14 分钟` | 常规 `--ink-2` |

要点：

- **"正在屙"才配脉冲**。待确认状态如果还脉冲，会让人以为记录还在正常进行，反而不去处理。
- **时长必须在阈值处停住**，不能一直涨到"已 3 天"。
- 「未记结束」用中性灰，不用红色 —— 它不是错误，只是没记。用红色会让人有负罪感，而这是个手帐类产品。

## 11. 已定 / 待定

**已定**

- **图标**：全部用 Lucide 矢量图标，禁止 emoji。
- **头像**：内置图标头像 + 首字色块兜底，同时支持上传照片（96px 缩略图缓存）。
- **月视图密度**：最多 2 个徽标 + `+N`，按**添加顺序**取前 2 个（不按次数排序，避免徽标位置随数据跳动）。
- **页面范围**：16 页，见第 9 节。
- **记录状态名**：「正在屙」（不用"进行中"）、「未记结束」、「时长不详」。
- **命名**：中文「屙了么」+ 英文 PoopedYet，包名 `com.poopedyet.app`。见 [naming.md](naming.md)。

**待定**

1. 要不要深色模式？手帐方向在深色下需要重新调一版（暖米纸换成深咖纸），大约多花 20% 工时。**注意：深色模式必须重跑对比度自检，不能直接沿用浅色的比例。**
2. 统计页做到什么程度？现在设计的是频次柱状图 + 按人分布 + 平均时长，还可以加"年度报告"这类分享向的东西。
3. **日历格里 9px 的头像图标几乎辨识不出形状** —— Lucide 是 2px 描边，缩到 9px 后 dog 和 cat 看起来差不多，实际区分主要靠底色。这不只是美观问题：**色盲用户会同时失去颜色和形状两条线索**。倾向在 ≤16px 的场景改用**姓名首字**（中文单字在极小尺寸下的辨识度通常高于线条图标）。需要真机确认。
4. 「待确认」的阈值默认 2 小时合不合适？短了会频繁打扰（拉肚子时可能真的待得久），长了就失去提醒意义。可能需要观察真实使用数据再调。
5. **整个 App 的读屏（TalkBack）语义标签还没设计过**。日历格现在是"11"+头像，读屏会念出一个孤零零的数字。
6. **日历格的触控目标** 46×58px，宽度低于 Material 建议的 48px 最小值，实现时要靠格子间距补命中区域。

> 完整的问题清单（含阻塞项、工程与合规）见 [review.md](review.md)。
